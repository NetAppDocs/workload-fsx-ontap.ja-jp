NetApp Workload FactoryのAmazon FSx for NetApp ONTAPに関するよくある質問では、FSx for ONTAPファイルシステムとストレージの計画、保護、管理方法に影響を与える概念、動作、制約について説明します。



[[links]]
== リンク

.リンクとは何ですか？また、FSx for ONTAPでリンクが必要になるのはどのような場合ですか？
リンクは、Workload Factoryと1つ以上のFSx for ONTAPファイルシステムとの間に信頼関係を確立し、AWS Lambdaを使用します。多くの操作には関連付けられたリンクが必要です。これには以下が含まれます：

* ボリュームのプロトコル アクセスの設定
* スナップショットとスナップショットポリシーの管理
* AIによるNetApp自律型ランサムウェア対策（ARP/AI）の有効化
* ボリュームの自動拡張および手動による容量変更の管理
* igroupとキャッシュボリュームの管理
* ONTAP資格情報の管理


link:links-overview.html["リンクの詳細"]。

.ファイルシステムにリンクを関連付けなかった場合はどうなりますか？
リンクに依存する機能は利用できない場合があります。例えば、リンクがないとARP/AIは利用できず、ボリューム作成時に既存のスナップショットポリシーを表示できず、キャッシュの関係性も検出できません。リンクがない場合、構成分析ではデータ保護とパフォーマンスの設定をスキャンできないため、分析が不完全になります。リンクがなくてもレイテンシイベントを表示することはできますが、EMSイベントの表示と分析、およびレイテンシイベントの分析にはリンクが必要です。



[[file-systems]]
== ファイルシステム

.新しいファイルシステムを作成する場合、クイック作成と詳細作成のどちらを使用すべきでしょうか？
クイック作成では推奨されるベストプラクティス構成が適用されますが、ほとんどの設定は後から変更できます。地域がサポートしていない場合を除き、デフォルトでは第2世代ファイルシステムが使用されます。高度な作成機能を使用すると、可用性、セキュリティ、バックアップ、メンテナンスなど、あらゆるオプションを設定できます。

link:create-file-system.html["ファイルシステムの作成"]。

.ファイルシステムを作成すると、どのようなリソースが自動的に作成されますか？また、どのような権限が必要ですか？
ファイルシステムを作成すると、ストレージVMとセキュリティグループも同時に作成されます。ファイルシステムの作成および削除権限を持つ認証情報に加え、デプロイ先のリージョンとVPCの詳細情報が必要です。

.ファイルシステム、ストレージVM、またはボリュームを削除する前に、何をする必要がありますか？
ファイルシステムを削除するには、まずそのボリューム、ストレージVM、およびレプリケーション関係を削除する必要があります。ストレージVMを削除するには、アプリケーションからのアクセスを停止し、ルート以外のすべてのボリュームを削除します。ボリュームを削除するには、まずそのレプリケーション関係を削除する必要があります。ボリュームを削除すると元に戻すことはできず、スナップショットも完全に削除されますが、ボリュームのバックアップは残ります。不変ファイルとスナップショットを含むボリュームは、保持期間が終了するまで削除できません。

link:delete-file-system.html["ファイルシステムを削除する"]。

.ファイルシステムをスケールアウトするためにHAペアを追加する前に、どのような点を考慮すべきでしょうか？
HAペアの追加は、第2世代のシングルAZファイルシステムにのみ適用され、HAペアは一度追加すると削除できません。この操作には約30分かかり、その間、ファイルシステムはボリューム作成などの他の操作には使用できません。開始する前に、すべてのiSCSI LUNを削除する必要があります。

link:add-ha-pairs.html["HAペアを追加する"]。

.プライマリと制限付きのONTAPクレデンシャルの違いは何ですか？
デフォルトでは、ファイルシステムは、ファイルシステムを管理するための主要な認証情報であるプライマリONTAP認証情報を使用します。制限付き認証情報は、Ask Me、Rule builder、Custom dashboardsなどのAI操作にのみ使用されます。制限付き認証情報を指定していない場合、Workload Factoryはこれらの操作用に読み取り専用のONTAP認証情報を作成します。認証情報の管理にはリンクが必要です。

link:manage-file-system-settings.html["ONTAP クレデンシャルの管理"]



[[capacity-and-performance]]
== 容量と性能

.自動キャパシティ管理はどのように機能するのですか？また、注意すべき点は何ですか？
Workload Factoryは30分ごとにファイルシステムをスキャンし、増分モード（しきい値での固定増加）または適応モード（履歴データから必要性を予測）を使用してSSD容量を追加します。有効になっている場合、手動で容量を増やす前に無効にする必要があります。AWSではSSD容量の追加間に最低6時間のクールダウン期間が適用されるため、データ移行中はこの機能を有効にしないでください。

link:adjust-file-system-capacity.html["ファイルシステムの容量を調整する"]。

.SSDの容量を変更すると、IOPSにどのような影響がありますか？
ファイルシステムの容量を変更すると、IOPSに影響します。自動IOPSプロビジョニングでは、追加または削除されたSSD容量1GiBあたりIOPSが3ずつ変化します。手動プロビジョニングの場合、容量を増やす前にIOPSを上げる必要がある場合があります。SSD容量の削減は、第2世代ファイルシステムでのみサポートされています。

.SSDにはどれくらいの余裕容量を確保しておくべきでしょうか？また、容量が不足した場合はどうなりますか？
SSD層の使用率を80%未満に抑えてください。容量が不足すると、ボリュームは読み取り専用になり、書き込みは失敗します。ボリュームとファイル（inode）の使用率も80%未満に抑える必要があります。バックアップスナップショットによってボリュームのSSD使用率が98%を超えると、バックアップは失敗します。link:adjust-file-system-capacity.html["スペース不足を避けるために容量を増やす"]。



[[volumes-and-tiering]]
== ボリュームと階層化

.ボリュームはファイルシステムの容量を消費しますか？また、FlexVolとFlexGroupのどちらを選択すべきですか？
ボリュームはデータを仮想的にグループ化するものであり、それ自体はファイルシステムのストレージ容量を消費しません。データは主にSSDストレージを消費し、階層化ポリシーによっては容量プールストレージも消費します。FlexVolはデフォルトのスタイルです。FlexGroupは、高性能かつ大容量のスケールアウトNASコンテナであり、トラフィックを共有する複数の構成ボリュームで構成されます。サイジングは異なります：FlexVolは20 MiBから300 TiBであり、FlexGroupは800 GiBから2 PiBで、構成ボリューム1つあたり100 GiBが必要となります。

.ボリュームのリバランスはどのような影響をもたらしますか？
リバランスは中断を伴いませんが、ボリューム転送はファイルシステムのリソースを消費します。リバランスされたボリューム上の既存のスナップショットは部分的なものとなり、ボリュームデータの復元に使用できなくなりますが、その後に取得されたスナップショットは復元に使用できます。SANボリューム（iSCSIおよびNVMe）では、リバランスはサポートされていません。FlexGroupのリバランスでは、レプリケーション関係にあるボリュームをサポートする制限付きレイアウトを選択しない限り、メンバーボリュームを追加してプロビジョニングサイズを拡張できます。

.ボリュームに対して、どの階層化ポリシーを選択すべきでしょうか？
ポリシーの選択はコストとパフォーマンスに影響します：

* *バランス（自動）*：デフォルト。一般的な主要ワークロードに推奨されます。
* *コスト最適化（すべて）*：セカンダリターゲットに推奨されます。
* *パフォーマンス最適化（スナップショットのみ）*：ミッションクリティカルなデータベースなどの低レイテンシワークロードに推奨されます。
* *なし*：すべてのデータをSSDに保存します。


ポリシーはボリュームごとに設定され、いつでも変更できます。

link:change-tiering-policy.html["階層化ポリシーを変更する"]。

.クローンされたボリュームとその親ボリュームはどうなりますか？
クローンとは、書き込み可能なボリュームのことです。そのデータは親ボリューム上に残っており、クローン上には新規書き込みのみが保存されます。クローンが存在する親ボリュームは、分割するまで削除できません。クローンを分割するには、クローンを含むファイルシステムへのリンクを関連付ける必要があります。分割はメタデータのみを更新するものであり、クローンがデータ保護関係にある場合は実行できません。分割後、2つのボリュームを再び結合することはできず、それぞれに十分な容量の割り当てが必要になります。



[[data-protection]]
== データ保護

.どのようなデータ保護方法を用いるべきですか？
組み合わせることをお勧めします。スナップショットを使用すると、最短1時間のRPOと、高速なファイルレベルの復元が可能になります。バックアップのRPOは1日からで、ボリューム全体としてのみ復元可能であり、復元には数時間から数日かかる場合があります。レプリケーションは、低RTOでの災害復旧のために別のリージョンにコピーを保持しますが、クライアントがレプリカを使用するように調整する必要があります。ARP/AIにより、ランサムウェア検出機能が追加されます。

link:data-protection-overview.html["データ保護の種類について学ぶ"]。

.スナップショットの容量計画はどのように立てるべきでしょうか？また、スナップショットはデータのコピーの代わりになるのでしょうか？
スナップショットはデータのコピーではありません。これらは変更されたデータのみに容量を消費するため、通常は時間の経過とともに容量が増加します。ほとんどのデータセットの場合、20%の追加容量があれば最大4週間分のスナップショットを保持できますが、すべてのデータを上書きするとかなりの容量を消費します。実際のコピーが必要な場合は、バックアップまたはレプリケーションを使用してください。

.スナップショットからボリュームを復元すると、どのような影響がありますか？
既存のボリュームにリストアすると、スナップショット作成後に変更されたデータはすべて完全に削除されます。新しいボリュームとしてリストアすると、サイズに関係なく数秒でコピーが作成されます。リストアによってNASプロトコルのタイプが切り替わると、権限モデルも切り替わる可能性があり、NASクライアントツールを使用して手動で修正するしかないファイルアクセスの問題が発生するおそれがあります。

.スナップショットポリシーについて知っておくべきことは何ですか？
変更しない限り、すべてのボリュームはファイルシステムの `default`スナップショットポリシーを使用します。ポリシーはストレージVMレベルで管理され、複数のボリューム間で共有できます。スナップショットの時刻はファイルシステムのタイムゾーンに従います。デフォルトではUTCです。

link:manage-snapshot-policy.html["Snapshotポリシーを管理します。"]。

.不変スナップショットとはどのような機能ですか。また、スナップショットやボリュームの削除にどのような影響を与えますか。
ボリュームスナップショットを作成する際に、不変性を有効にすると、スナップショットの保持期間中は変更や削除ができなくなります。スナップショットポリシーで不変スナップショットを有効にすると、そのポリシー内のすべてのスナップショットがロックされます。不変ファイルとスナップショットを含むボリュームは、保持期間が終了するまで変更または削除できません。

.ボリュームで不変ファイル（SnapLock）を有効にする前に、何を決定しておく必要がありますか？
不変ファイルはボリューム作成時にのみ有効化でき、作成後に無効化することはできません。これは追加料金のかかるプレミアム機能です。保持モードを選択してください：エンタープライズモードではSnapLock管理者は保持期間中にファイルを削除できますが、コンプライアンスモードでは、WORM ファイルは保持期間が満了する前に削除できず、ボリュームも同様です。不変ファイルを含むソースボリュームを複製すると、ソースの保持期間が終了するまで、ターゲットボリュームとファイルシステムはロックされたままになります。

link:create-volume.html["ボリューム作成時に変更不可能なファイルを有効にする"]。

.ボリュームバックアップはどのように機能し、どのような原因で失敗する可能性があるのでしょうか？
バックアップはボリュームごとに行われ、増分バックアップとなるため、前回のバックアップ以降に変更されたデータのみが保存されます。バックアップスナップショットによってボリュームのSSD使用率が98%を超える場合、バックアップが失敗する可能性があります。バックアップはAWSアカウント内の任意のFSx for ONTAPファイルシステムに復元でき、復元に必要な場合はWorkload FactoryでSSD容量を追加できます。手動で作成したバックアップは自動的に期限切れにならないため、古いバックアップは削除してください。

link:use-backups.html["バックアップでデータを保護する"]。

.cyber vaultとは何ですか？どうすれば入手できますか？
cyber vaultは、ランサムウェアや内部脅威から保護する、隔離され、エアギャップされた、変更不可能なバックアップコピー用リポジトリです。FSx for ONTAPは、cyber vaultのソースおよびターゲットとしてサポートされています。NetAppは実装を支援します：ng-FSx-CyberVault@netapp.comのcyber vaultチームにお問い合わせいただければ、専門家が対応いたします。

link:create-cyber-vault.html["cyber vaultの詳細について"]。



[[ransomware-protection]]
== ランサムウェア対策

.ARP/AIはどのように機能し、何が必要ですか？
ARP/AIは、NAS（NFS/SMB）およびSAN（iSCSI）ボリュームを監視します。脅威を検知すると、変更不可能なスナップショットを作成します。ファイルシステム上でこれを有効にすると、既存のボリュームと新規ボリュームすべてが保護され、関連付けられたリンクが必要になります。NVMeボリューム、または9.17.1より前のONTAPを使用するiSCSIボリュームではサポートされていません。NASの保護は即座に開始されます。一方、SANボリュームは2～4週間の学習期間を経ますが、その間も監視は継続されます。

link:ransomware-protection.html["ARP/AIによるランサムウェア対策"]。

.ARP/AIが攻撃を検知した場合、どのような処理が行われ、誤検知はどのように対処されるのでしょうか？
ARP/AIは、脅威を検出した時点でロックされたスナップショットを作成します。デフォルトでは、ARP/AIは4時間ごとに最大6つのスナップショットを作成し、それぞれ2～5日間ロックされます。実際に攻撃があったことが確認できた場合は、影響を受けたファイルまたはボリューム全体を復元できます。誤報としてマークすると、ロックされたスナップショットは削除され、システムはアラート設定を更新するため、次回同じファイル拡張子ではアラートが発生しなくなります。



[[replication-and-migration]]
== レプリケーションと移行

.レプリケーション関係を作成する前に、どのような準備が必要ですか？
必要なもの：

* 関連付けられたリンクを持つターゲットのFSx for ONTAPファイルシステム。
* ストレージシステム間でTCPポート11104と11105が開かれています。
* ソースである場合は、検出されたオンプレミスのONTAPシステム。


レプリケーションは、FSx for ONTAPファイルシステム、オンプレミスONTAPシステム、およびCloud Volumes ONTAP間で機能します。レプリケートされたボリュームは、 `\{OriginalVolumeName}_copy`という名前のデータ保護ボリュームです。

link:create-replication.html["データのレプリケート"]。

.レプリケーション関係を一時停止、停止、再開、反転、または削除した場合、データはどうなりますか？
一時停止または停止すると、ターゲットボリュームへの書き込みが可能になります。再開すると、書き込み可能であった間にデスティネーションに加えられた変更はすべて削除され、読み取り専用に戻ります。リバースすると、ソースとターゲットの役割が入れ替わり、新しいターゲットが新しいソースの内容で上書きされます。関係を削除すると、両方のボリュームは独立した状態になりますが、共通のレプリケーションスナップショットは削除されます。前回のレプリケーション以降にソースに書き込まれたデータは、リバースまたは再開時に保持されません。

link:manage-replication.html["レプリケーションの管理"]。

.カスケード型レプリケーションはいくつのホップをサポートし、そのトレードオフは何ですか？
カスケードレプリケーションは、データ保護ボリュームのレプリカを1つサポートします（2ホップ目：ソースからセカンダリ、そしてターシャリへ）。3つ目のホップはサポートされておらず、ベストプラクティスとは見なされません。カスケード機能を使用すると、セカンダリが利用できなくなった場合に、新しいベースライン転送なしでプライマリボリュームとターシャリボリュームを再同期できます。カスケードされたボリュームの再同期には時間がかかる場合があり、ソース自体が別のリレーションシップのターゲットとなっているデータ保護ボリュームであるリレーションシップを元に戻すことはできません。

link:create-replication.html["データ保護ボリュームのカスケードレプリケーション"]。

.レプリケーション関係の転送速度を制限する必要がありますか？
最大転送速度の制限は任意ですが、推奨されます。制限を設けないと、ネットワークやアプリケーションのパフォーマンスが低下する可能性があるためです。主に災害復旧に使用されるファイルシステムなどの重要なワークロードの場合は、転送速度を無制限にすることを推奨します。

link:manage-replication.html["レプリケーション関係の最大転送速度を制限する"]。

.ストレージVMを移行し、レプリケーションを切り替える際に、どのようなことを計画すべきでしょうか？
移行には3つの操作が必要です：関係の作成（ユースケースとして*移行*を選択し、*ストレージ VM 構成の複製*を選択）、初期化、および切り替え。切り替え前に、クライアントのアクセスを停止し、データが同期されていることを確認してください。ソースとターゲットは同じメジャーONTAPバージョンを実行する必要があります。切り替え後、ソースストレージ VM はオフラインになり、LUNシリアル番号とiSCSIターゲットIQNが変更されるため、iSCSI、MTU、およびDNSの設定を手動で更新する必要があります。

link:create-replication.html["データのレプリケート"]。



[[s3-access-points-block-storage-and-cache-volumes]]
== S3アクセスポイント、ブロックストレージ、キャッシュボリューム

.S3アクセスポイントとは何ですか？また、インベントリやジャーナルテーブルなどの機能を有効にする前に知っておくべきことは何ですか？
S3アクセスポイントはNFSおよびSMBボリュームに接続されるため、Amazon BedrockなどのAWSサービスは、ファイルデータがS3バケット内にあるかのように読み取ることができます。1つのボリュームに複数のアクセスポイントを接続できます。インベントリテーブルはオブジェクトのメタデータを生成し、AWS S3リクエストのコストが発生します。ジャーナルテーブルの監査ログにはAWSインフラストラクチャ（CloudTrail、CloudWatch、S3、IAM）が必要であり、アクセスポイントのネットワーク構成が*Internet*である必要があります。

link:create-s3-access-points.html["S3アクセスポイントを作成する"]。

.ブロック（iSCSI）ストレージをセットアップするには何が必要ですか？
リンク、FlexVolボリューム、およびigroupが必要です。ブロックアクセスは、HAペアが6組以下のスケールアウト環境でのみ利用できます。igroupはIQNによってホストにアクセス権を付与します。iSCSIを機能させるには、igroupとiSCSIホスト接続の両方が必要です。構成分析では、iSCSIボリュームでNASアクセスを同時に許可しないことが推奨されています。

* link:https://docs.netapp.com/us-en/workload-setup-admin/create-link.html["リンクの作成"^]。
* link:create-volume.html["FlexVol volumeの作成"]。
* link:create-igroup.html["igroupの作成"]。
* link:create-block-device.html["ブロックデバイスを作成する"]。


.使用されていないブロックデバイスはどうなりますか？
クライアントにマッピングされていない、または7日間連続して使用されていないブロックデバイスは、非アクティブと分類されます。SSDの容量を解放するために、そのデータを容量プール層にアーカイブするか、削除することができます。構成分析では、非アクティブなブロックデバイスをコスト最適化項目として検出します。

.キャッシュ書き込みモードはどのように選択すればよいですか？また、キャッシュボリュームを管理するには何が必要ですか？
ライトアラウンドモードは、読み込み負荷の高い小規模ファイル処理において優れたパフォーマンスを発揮し、ライトバックモードは、書き込み負荷の高い大規模ファイル処理において優れたパフォーマンスを発揮します。Workload Factoryは既存のキャッシュ（FlexCache）関係を検出します。キャッシュボリュームを検出または管理するには、リンクを関連付ける必要があります。

link:manage-cache-volumes.html["キャッシュボリュームを管理する"]。



[[configuration-analysis-and-monitoring]]
== 構成分析と監視

.構成分析はどのように機能するのですか？また、修正プログラムを自動的に適用しても安全ですか？
Workload Factoryは、ONTAPのベストプラクティスおよびAWS Well-Architected Frameworkの柱（信頼性、セキュリティ、運用上の卓越性、コスト最適化、パフォーマンス効率）に照らして、構成を毎日分析します。一部の問題は自動的に修正でき、その他の問題については手動での手順を提示します。修復作業はダウンタイムやサービスの中断を引き起こす可能性があるため、まず各推奨事項を確認してください。お客様の環境に適用されないチェックは無視することができます。

Workload Factoryが構成を分析できるようにするには、AWSアカウントでlink:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["操作と修復の権限を付与する"^]する必要があります。

link:improve-configurations.html["設定を評価する"]。

.AIを活用したイベント分析を利用するには何が必要ですか？
必要なもの：

* link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["_操作および修復_の権限。"^]。
* リンク。
* ファイルシステムのセキュリティグループでポート22が開放されている。
* Amazon Bedrockがアカウントに対して有効化され、必要なBedrock IAM権限が付与されています。


イベントは72時間表示された後、削除されます。データはお客様のAWSアカウント内に保持され、顧客データはモデルのトレーニングには使用されません。アカウント管理者がAI機能を無効にしている場合、分析機能は利用できません。

link:analyze-events.html["イベントを分析する"]。



[[costs-and-support]]
== 費用とサポート

.削減額計算ツールはどのように機能し、どのような権限が必要ですか？
この計算ツールは、Amazon Elastic Block Store（EBS）、Elastic File System（EFS）、およびFSx for Windows File Serverのコストを、FSx for ONTAPと比較します。詳細情報を手動で入力することも、Workload Factoryに環境を自動的に検出させることもできます。ただし、環境を検出するには、*表示、計画、および分析*の権限が必要です。自動検出は、EBSスナップショットやFSx for Windows File Serverのシャドウコピーをサポートしていません。

link:explore-savings.html["削減額計算ツールの使用方法"]。

.コスト追跡データはどこから取得され、どの程度最新ですか？
コストデータは、 `ce:GetCostAndUsage`および `ce:GetTags`権限を使用してAWS Cost Explorerから取得され、24時間ごとに更新されます。Workload Factoryは、独自の推定値に基づいてリソースごとのコストも算出します。AWSのコスト配分タグでフィルタリングするには、ファイルシステムにタグを割り当てる必要があります。

link:track-costs.html["コストを追跡する"]。

.FSx for ONTAPアカウントの管理は誰が行い、ファイルシステムの問題に対するサポートは誰が提供しますか？
お客様のFSx for ONTAPアカウントを保守するのはAWSであり、Workload Factoryではありません。ファイルシステムまたはインフラストラクチャに関するサポートの問題については、AWS Management Consoleのサポートセンターを使用してAWSサポートケースを開き、FSx for ONTAPサービスを選択してください。Workload Factoryに関する一般的な質問については、link:get-help.html["ヘルプページ"]を参照してください。
